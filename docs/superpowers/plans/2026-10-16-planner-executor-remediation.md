# Planner–Executor 运维主链路改造

**目标：** 将用户已确认的动态规划方案接入告警主链路，替换固定证据采集和独立报告型多 Agent。保留告警聚合、事务消息、执行隔离、权限检查、冷却、审计和实际恢复验证。

**架构：** Spring AI Alibaba 1.1.0.0-RC2 的 StateGraph 驱动 Planner / Executor 两个 ReactAgent。Planner 返回结构化单步计划，Executor 只能调用当前计划对应的绑定工具；真实观察结果重新交给 Planner。Graph 是执行引擎，不预设调查顺序。任务检查点与计划、观察结果保存到已有事故诊断 JSON，执行记录继续使用已有动作表。

## 边界

- 复用本机 SDKMAN JDK 17.0.19-amzn、Maven 3.9.16；不升级框架或新建中间件。
- 保留开始前已有的告警聚合代码和未完成文档，不回退、不混入其他项目。
- Agent 不持有 Docker Socket、不执行 Shell、不修改业务代码或构建未知镜像。
- 写操作必须有实际采集的证据、已检索的批准 Runbook 和服务策略许可。
- 完成必须有真实健康验证；预算不足只能分段恢复或转人工，不能伪报成功。
- 自动告警、人工调查和旧分析入口共用事故队列与同一运维核心。

## 修改范围与步骤

1. 新增 `incident/agent`：计划、观察、检查点、受控工具、原生 Agent 构建和 Graph 运行器；先增加测试验证虚假完成、越权工具、无工具调用和不同查询顺序。
2. 修改 `AutonomousIncidentOrchestrator` 为任务生命周期与服务租约管理；调整 `WorkflowPersistence` 和事故状态转换，允许根据模型计划回到调查，不改变告警聚合。
3. 合并旧模型诊断和报告编排入口：`AiOpsService` 成为统一任务入口，旧 Webhook 桥接同一队列；聊天增加发起与查询工具，旧 `/api/ai_ops` 不再单独运行 Supervisor。
4. 为现有 Vue 控制台加入沿用原样式的助手面板、计划和最终记录展示。业务阶段与工具事件来自数据库时间线，不暴露原始系统提示词。
5. 只运行新增及直接受影响的后端测试、前端构建；联调复用 AIOps 专属环境，先确认容器归属与状态，不操作其他项目。

## 验收

- 脚本化模型通过真实框架驱动不同查询顺序并反馈工具证据。
- 未查证即 FINISH、Executor 只说完成却未调用工具、未批准操作均不能造成修复成功。
- 重建后验证失败能回滚，未知执行结果不能盲目重放。
- 分段恢复沿用计划的幂等标识，轮数、失败次数和任务预算有代码边界。
- 普通聊天不直接拥有 Docker 工具，仅能调用统一任务入口与查询事故记录。

框架回归测试不依赖真实 LLM，不宣称模型准确率或生产效果。另已开展真实模型只读调查、503 故障受控重启闭环，以及聊天发起和查询联调，具体结果、环境隔离及未验证边界见 `docs/PLANNER_EXECUTOR_OPERATIONS.md`。
